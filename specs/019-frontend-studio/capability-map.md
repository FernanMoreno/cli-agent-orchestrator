# Matriz de cobertura integral de CAOS Studio

Baseline: 2026-10-10. Inventario desde fuente y documentación contrastada. Todas las pantallas propuestas están pendientes de implementación; «existente» describe la capacidad del producto, no la cobertura del rediseño.

## Organización propuesta

- **Trabajo**: Inicio, Ejecuciones, Agentes, Workflows, Tareas, Interacciones.
- **Biblioteca**: Perfiles y prompts, Conocimiento, Skills y extensiones.
- **Operación**: Automatizaciones, Instancias y workers, Terminales, Actividad y diagnósticos.
- **Administración**: Configuración, Acceso y cuenta, Ayuda y disponibilidad de funciones.

Un detalle contextual conecta áreas: workflow → ejecución → paso → Work/intento → agente → terminal/pregunta → resultado. No exige nuevas identidades de proyecto compartido ni altera autoridades existentes.

## Puerta de cobertura total

Durante plan/tareas cada fila se desglosa por operación en estado **por diseñar / necesita contrato / implementada / verificada / indisponible por capacidad / interna con recorrido humano definido**. Solo se acepta «verificada» con evidencia sobre su frontera real. Disponibilidad condicionada no exime de diseñar el recorrido cuando la función se habilita.

Todas las filas requieren los controles de ámbito/permisos, revisión de errores e incertidumbre, borradores cuando haya autoría, accesibilidad y recuperación. El inventario de [superficies declaradas](surface-inventory.md) se vuelve a generar y contrastar con OpenAPI/comandos reales en implementación para detectar operaciones nuevas o montajes dinámicos. Este baseline no certifica que cada endpoint esté actualmente servido ni que cada comando sea seguro para exposición remota.
