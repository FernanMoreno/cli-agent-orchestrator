## Finding

**P2 — Native provider skill scanning bypasses the new current-content approval guard.** `src/cli_agent_orchestrator/services/install_service.py:699` gives Kiro native globs over the entire global skills directory; `src/cli_agent_orchestrator/utils/opencode_config.py:101` gives OpenCode a symlink to that entire directory. Install and explicitly approve a plugin, then change its installed valid `SKILL.md`. `delivery_allowed` correctly becomes false, and the new CAO runtime catalog/content guard rejects it. However, the physical projected link remains until an explicit rebuild, and native provider directory scanning still resolves the changed file. A fresh launch can therefore consume instructions whose content was never approved. This differs from the documented limitation of already-running clients retaining snapshots. C-006 and the approved exact-content policy require changed plugin content to remain disabled at these consumers too. Source search found no launch-time projection reconciliation in the current providers/terminal lifecycle. The existing tamper regression in `test/agent_plugins/test_no_auto_grant.py:719` itself explicitly rebuilds only after checking CAO catalog refusal; it does not exercise the native scan between tamper and rebuild. Reported immediately to root and the US5 owner for reproduction/correction. Status at report creation: pending owner fix and regression evidence.

**Re-review:** The original native-content bypass is corrected in source by `projection.reconcile_native_skill_projection()` and the pre-launch call in `terminal_service.create_terminal`. The lifecycle-locked reconciliation rebuilds approved projections, then checks structural ownership and explicitly raises when an unapproved managed entry cannot be removed. Native initialization occurs afterwards. The four native-provider/revocation cases exercise the real `create_terminal` control flow with real filesystem scans and a controlled provider initialization seam; ordinary user skills survive. The API list now supplies a current review as well as stored metadata, and its tamper regression confirms `enabled=false` after modification.

**P2 follow-up, resolved — Reconciliation must leave the shared event loop responsive.** The initial fix called synchronous reconciliation directly from async `create_terminal`, allowing the default 60-second lifecycle lock and full plugin tree hashing/rebuild to freeze other requests. Reported immediately to root and US5 owner. Re-review confirms `terminal_service.py:1743` uses `await asyncio.to_thread(reconcile_native_skill_projection)`, consistent with neighboring worktree and session-lock offloading. The final `/home/felni/tmp-us5/native-final.log` reports **4 passed, 28 deselected** in 24.57 seconds, covering successful revocation and refusal to launch when revocation fails for both native providers after the offload change.

No other verified P1/P2 defect was found in the scoped implementation.
