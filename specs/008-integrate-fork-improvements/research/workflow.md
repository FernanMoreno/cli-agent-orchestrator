### Ralph and semantic coordinator

Fork clients/ralph.py:12-24 state tracks prompt, iteration, min/max, completionPromise, taskId/workDir, prior feedback, active/status/start time. :40 start, :56 status, :59 stop, :68 feedback increments/caps, :88 complete. Implement equivalent usable iteration controls on one durable Work coordinator, not two incompatible Ralph stores.

Functional preservation: start/status/stop/complete, task/workspace association, min/max iterations, promise/criteria, scored feedback summary/improvements/next steps/ideas/blockers, previous iteration context, iteration cap and user-visible reason, CLI/MCP/API/UI. Strengthen input bounds and semantics: explicit complete is user operation with evidence; automated complete requires criterion validation. Stop means stop-proof/uncertainty contract, not a bool flip. Running stays observable across restart without blindly adopting/resending old process.

G03 missing from every examined branch: a durable checkpoint controller distinguishing delivery/execution/verified receipt/accepted Work result/semantic objective. Current workflow_service.py:2293-2305 reserves loop/on_stall/on_no_progress as NotBuiltYet; AGUI dashboard is projection; outcome_service stores declared feedback. Existing artifacts are content-addressed but do not prove current working-tree validity.

Best equivalent controller requires:
- Task/checkpoint acceptance criteria, explicit current attempt/generation and authorized target/tool inventory; progress observations reference evidence/artifact digests/revision and timestamps.
- Event plus bounded low-frequency durable observation, deduplicated per attempt/generation, separate observation and execution budgets. Pending/reconcile stays uncertainty. Never corrective repaste/retry while active turn delivery uncertain.
- No-progress detection based on checkpoint/evidence deltas, not self-reported quality score. Corrections bounded to current approved tools/targets/context; send via existing inbox only when receiver accepts input.
- Freshness validators inspect current target revision/hash/files/tests before accepting old report; retain old immutable snapshot and create new follow-up context, never rewrite past evidence. Refuse missing/withdrawn snapshots and unauthorized context.
- Durable iteration/correction history, budget/deadline/escalation with concrete cause/evidence/next action; successful correction -> measurable checkpoint progress; repeated useless correction -> bounded stop/escalation.
- Integrate G01 late-receipt reobservation and G02 accepted-result continuation in current engine, not second workflow runner. `submit_workflow_step_result` currently persists authenticated result; projector pending drive exists but no proven durable auto-resume hook. Add outbox/continuation queue from accepted result transaction, fenced single driver, crash replay. Handle revoke/stale generations before effects.
- Dependencies: repair B01 post-delivery timeout retry, B02 provider partial restoration, B03 persistence-dependent budget, B05 running-without-owner first; assignment R01 identity needs a real response-loss integration test. Parent can own these separately.

2. Current source rollback/index semantics vs latest file-canonical semantics need test/docs migration; do not silently preserve rollback race.
3. Plan-v2 + WorkContractV2/private snapshots must share bindings/authority/transactions. Schema migration supports historic plan-v1 manifests and existing Work contracts without granting new authority.
4. Fork frozen-memory legacy resolver may bypass current per-job knowledge access if imported whole. Use DelegationSnapshots/FrozenRunMemoryCapability.
5. Older Beads assignment swallows failures and has per-process asyncio lock only; use durable intent/receipt fencing. Bead 'closed' is not independent semantic proof.
6. Fork master prompt says kill-and-redispach stuck agents; replace with stop proof and existing recovery. Ralph min/promise alone aren't enforced completion criteria.
7. Dynamic PR-health inputs and approval identity: date/snapshot changes are execution-affecting. Scheduled apply behavior must use explicit scoped standing authorization if supported, or surface review; example registration is not performed by this implementation.
8. Preserve all dirty Spec007 changes and current browser auth/base-path/Work feature flags. Import only selected functional deltas, never replace giant divergent modules.
