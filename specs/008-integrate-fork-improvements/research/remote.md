## Runtime source: exact new modules and interfaces

New directory `src/cli_agent_orchestrator/runtime_channel/`:

- `protocol.py`: protocol version1; tagged Pydantic Hello/Command/Result/Status frames, JSON text encode/decode. `Hello(protocol_version,runtime_id,statuses)`; runtime ID one safe URL segment `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`. `Command(op_id,type,terminal_id,payload)`, `Result(op_id,ok,payload,error)`, `Status(terminal_id,status)`. Commands LAUNCH, INPUT, KEY, OUTPUT, WORKING_DIRECTORY, EXIT, DELETE. **No wire runtime-incarnation, turn generation, operation replay identity, sequence counter, durable command journal, or CANCEL/VERIFY** in source v1.
- `token.py`: shared runtime token read once under thread lock; file wins (`CAO_RUNTIME_TOKEN_FILE`) over env (`CAO_RUNTIME_TOKEN`). Both values/path env variables popped before launching children; header `x-cao-runtime-token`. Empty/unreadable token yields None, server refuses all channel connections. Constant-time bytes compare in server; credential mismatch rejects before websocket accept (HTTP403). No token query parameters. Rotation requires process restart; not browser/local API bearer. Preserve path/value removal and redact diagnostic/error content (file path logging is source behavior, not secret token output).
- `registry.py`: thread-safe live connection/status/placement maps; RuntimeConnection correlated Future per op, send lock, whole-call deadline (lock+send+result), 60s commands and240s launch. Before write unavailable503 safe retry; send/result uncertain504 never automatically retry; failed remote command502. Old connection closed on replacement; queued writes recheck closed under send lock; no command until hello activated; pending callers fail unknown on disconnect; loop thread refuses blocking self-call. Status keyed `(terminal_id,runtime_id)` and only current owner/connection accepted; newer pushed status cannot be overwritten by older launch result. In-memory reservation holds launch between result and central row. **Placement durable only through central terminal row.runtime_id; maps/pending ops/reservations/cleanup tasks are not durable Work evidence.**
- `server.py`: separate APIRouter `WS /runtime/channel`, `GET /runtimes` read/write/admin, `POST /runtimes/{runtime_id}/terminals` write/admin. Launch body profile/provider/working_directory; validates returned terminal ID/provider/session/name/engine before central recording, unique session name/terminal conflicts, preserves runtime engine/allowed tools. Shared session_lifecycle_lock and atomic runtime claim prevent losing launch from disturbing winner. Hello restores recorded placements from DB, rechecks deleted rows, accepts only owning status and cleans unrecorded remote terminals. Reservations prevent reconnect from deleting result still being committed. Launch task strongly tracked, shielded after frame is sent; pre-send cancellation cancels launch; late unclaimed result triggers compensating delete. Confirmed launch record is not reported as failure merely because subsequent projection/plugin notification failed. `CAO_RUNTIME_LAUNCH_TIMEOUT` positive override; compensating deletes exponential5..60s until confirmation/channel ends, next hello retries. Server `_settlements`/`_teardowns` task sets must be lifecycle-owned in our integration (drain/admission fence, no untracked tasks).
- `bridge.py`: execution-only outbound client, no HTTP server. `CAO_BRIDGE_SERVER_URL`, `CAO_BRIDGE_RUNTIME_ID`, token above, optional `CAO_BRIDGE_READY_FILE` default CAO_HOME/bridge-ready. Protocol/token refusals stop (no futile reconnect); network failure backoff1..30s resets only after10s stable hello; Ready file only while accepted channel active. Commands on same terminal run FIFO under refcounted locks; different terminals/launches concurrent. Deletes wait for in-progress launches that could create that terminal, not every old terminal. Unsent Result frames retained across websocket reconnect; status pushed after launch result to avoid unknown pre-placement drop. Forwarder isolates one failed status push. Uses local terminal_service/backend; strips stale rows only when strict session absence proven. Source `_drop_stale_rows` uses session-name deletion and should be upgraded to C04 exact/incarnation proof. Stops main monitor/log/status tasks on exit; own per-command tasks/unsent queue also need bounded/drained ownership in our version.

### Required adapter safeguards beyond source v1

1. **Durable placement and operation intent**: bind server-generated stable op_id to principal/Work grant revision/job/item/attempt/generation, request hash, runtime ID AND runtime incarnation, terminal ID AND session/backend incarnation, creation/deadline/send/result/settlement. Reuse LaunchRuntime `_operation_request`/admit_launch and current Work repositories; terminal row runtime_id is projection, not sole authority. Persist intent before effects; same op_id+same payload replay returns current/settled operation; conflicting hash rejected, never second launch.
2. **Runtime channel identity**: hello carries explicit persistent runtime incarnation/connection generation and capabilities/protocol version; authenticate runtime to configured permitted runtime ID/scope (shared token without scope otherwise allows claiming any ID). New incarnation must not adopt old processes by runtime name alone; reconnect of same incarnation reconciles operation/placement inventory, changed incarnation yields lost/unknown without releasing holds absent stop proof.
3. **Result/status fences**: validate op_id request association, allowed response shape, runtime/terminal incarnation, attempt/turn generation/sequence; stale old connection result/status ignored. Status COMPLETED remains visual telemetry; only007 verified receipt + authenticated accepted Work result settles its contract. Runtime OUTPUT must carry same pending202/reconcile409/verified semantics, not plain text success.
4. **Send cancellation uncertainty**: distinguish not-started write from potentially partial send; once send attempted may be accepted, persist uncertainty and shield durable settlement. Transport cancellation/timeout/disconnect never proves worker stopped nor authorizes retry. Branch pre-send sent-event handles local cancellation but has no durable shared command replay fence; strengthen with intent before send. No re-send INPUT after ambiguous delivery.
5. **Cancellation and compensating delete**: provide generation-fenced VERIFY/CANCEL equivalents over protocol (or explicit scoped recovery operation), using local turn_recovery_service and exact backend object evidence. Compensating DELETE uses exact runtime+terminal+session incarnation and immutable operation target; never source's name-only kill or deletion of new runtime with reused ID. Persist pending teardown with backoff/deadline window, reconnect/startup replay, dedupe. Success requires confirmed exact absence; unreachable remains reconcile and capacity hold. Keep source launch result reservation/late-result/hello compensation behavior but defer deleting legitimate durable in-flight work until matching intent reconciled.
6. **Credentials/context**: runtime-channel token never agent env, logs, URI, workflow inputs/public status; runtime receives only allowed provider configuration/approved frozen plan+snapshot needed for job. Work attempt/receiver credentials scoped/current and validated at central result submission; local API/browser/runtime/elastic/fleet panel tokens distinct. Default no runtime token means channel refused.
7. **Lifecycle/limits**: bound incoming frame size and typed payloads/op_id; cap queued/inflight commands and unsent results; own/drain server settlement/cleanup/registry and bridge command tasks; shutdown admission fence. Budget diagnostic persistence separate from execution/observation and maintain durable unknown state on DB outage. Source websocket max_size16MiB is bridge receive cap, not a complete server queue bound.
