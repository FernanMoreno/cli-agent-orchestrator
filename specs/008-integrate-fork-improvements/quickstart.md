# Validation quickstart

Prerrequisitos: .venv del proyecto, dependencias frontends/TUI y tmux para integración aislada. No usar sesiones personales ni cambiar credenciales.

1. Ejecutar regresiones nuevas de008 y suites de sus módulos con PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest --no-cov -p no:cacheprovider.
2. Reproducir post-send timeout con worker PROCESSING, DB outage del verificador y restart restore failure; comprobar no segunda entrega/no LAST histórico/límites independientes.
3. Respuesta tardía auténtica tras reconcile y reinicio: resolver mismo attempt sin repaste; cancel y generación nueva rechazan evidencia antigua.
4. Comparar todas las interfaces con202/409/500 y verify/cancel, roles/globs/[] y permisos efectivos instalados.
5. Autoría create/update CAS, aprobación y cambios de material; continuation tras accepted result y evento repetido.
6. Modelo causal735 adaptado + receipt007: frames antiguos, clear/delivery interleavings y backstop no generan falso éxito.
7. Grafo con cold build/request timeout/retry/cola; Apps recursos ausentes/restricción y permisos; fleet routing/nodos caídos.
8. Kimi familias/swarm, Kiro versiones/KAS, panes/identity/cleanup/FIFO, bridge reconnect/launch cancellation sobre entorno aislado.
9. Ejecutar checks de arquitectura, builds y project-composition-check; revisar ledger coverage.json. Todo verified requiere evidencia, no sólo que exista el archivo.
