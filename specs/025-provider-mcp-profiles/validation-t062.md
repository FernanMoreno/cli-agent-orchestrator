## Correction and authority

A strict active/retiring phase records validated removal intent before recursive deletion; it is separate from launch identity. Old v1 receipts without this field are interpreted as active. Its terminal identity, dialect, random root basename, nonce, device/inode and matching root marker authorize only the indexed launch. Reconstruction binds to the observed launch; stale instances cannot retire its replacement. Lookup does not scan other terminal directories. Existing random directory layout, turn receipts, generations, model policy, task budgets and permissions are unchanged.

Index/marker reads reject links, hardlinks, foreign or nonprivate files, oversized or malformed content, wrong keys/types/identities and duplicate JSON keys. Both use the same strict decoder. Deletion or publication errors return retryable failure; manager registry retention remains authoritative. Historical unindexed roots and RECONCILE_REQUIRED jobs are neither adopted nor removed. Fresh unused cleanup creates no state; a reconstructed terminal without proof conservatively refuses cleanup.
