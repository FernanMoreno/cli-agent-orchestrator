# T051 — active native-v1 credential selection (implementation verified)

The operator's active Go key in the current vendor store differs from the legacy JSON key. Production v1 previously copied only that JSON. This proves incorrect source selection; it does not prove expiration or explain a historical timeout.

The v1 provider now honors explicit inline JSON first, otherwise copies a stable private vendor state bundle, resolves the effective provider from launch/agent/global model precedence, and asks the pinned native CLI to export only its active key. It stages the selected key in native v1 auth format and removes the snapshot before terminal launch. Empty legacy native stores retain JSON compatibility; a nonempty current store with absent, ambiguous, malformed or unsupported OAuth selection fails closed. Operator credentials remain untouched.

CAOS does not open a vendor database driver. The export uses the vendor's own [native db command](https://raw.githubusercontent.com/anomalyco/opencode/53d1eabb61e21162157817bf677da0a4ad3332e3/packages/opencode/src/cli/cmd/db.ts) on the private snapshot, a bounded fixed SELECT, closed environment, separate process group and asynchronous timeout/cancellation. Runtime output containing keys is never logged. The original PostgreSQL-only source guard is unchanged. Initial synthetic-driver fixture results are retained but superseded by opaque vendor files and mocked CLI-boundary contracts.

Reproduction: revised vendor-boundary RED had 17 failures/two controls. Initial GREEN passed 19 cases. Lifecycle and envelope review expanded to 28; review caught a missing-table substring accepting a different table name (one RED/27 controls). Exact table matching corrected it: all **28 passed**. Cases cover active/stale selection, model precedence, custom path/WAL, source nonmutation, inline priority, legacy compatibility, refusal, cancellation, timeout/forced termination before snapshot removal and event-loop responsiveness.

Expanded serial regression: **475 passed**, two existing warnings, **184.79 s**, admission **7,281 MiB** against the unchanged 6,144 MiB floor. All 13 selected modules retained their normal markers/coverage, including the unchanged PostgreSQL-only guard, v1/v2/native policies, installer and preallocation. Canonical typing passed **405 files**; Black/isort passed the three changed Python files; architecture/composition kept **five contracts, zero broken**. This focused suite is not the global coverage gate.

A serialized actual-vendor diagnostic also passed on the reviewed uncommitted bytes: production snapshot/export helper with pinned **1.18.35**, current operator store and the actual auth-free native-v1 empty store from T049. Admissions **7,212 / 7,224 MiB**; both CLI children exited0/reaped, active selected API export and empty-store fallback signal matched, snapshots removed, operator auth/source/binary unchanged. Composition review: model/config → stable owned vendor snapshot → native CLI export → strict response validation → private native auth → backend startup. Ownership, no credential inheritance, exact selection, timeout/cancellation ordering and failure propagation were checked against source and the contracts above. No CAOS persistence, message/event schema or operation authority changes. Bounded Graphify refresh and final diff review accompany integration; generated main graph remains untouched by publication.
