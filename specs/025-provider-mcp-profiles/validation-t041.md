# T041 — validate and freeze native OpenCode profiles before allocation

## Reproduction and correction

The existing create_terminal path performed OpenCode's native profile validation only during provider initialization, after generating the terminal identity and potentially creating a child receipt, worktree, backend window, row and FIFO. The new regression module first produced **23 failures and 3 controls passing**: twenty malformed/missing/pending profile combinations reached the allocation sentinel, and three snapshot/manager contracts were absent. The matrix covers root/child and eager/deferred requests without allocating a real resource.

NativeAgentSnapshot freezes the canonical selected identity, bare native payload and immutable managed policy. OpenCode's read-only loader validates the installed native profile, mode/envelope and ready-policy configuration binding without probing a vendor executable. create_terminal calls it off the event loop before new identity/child/backend/state allocation. ProviderManager transfers it only to a matching OpenCode provider, before publication. Initialization and interaction-capability discovery consume the same prepared snapshot; current configuration binding is checked again before launch. A later native-file replacement therefore cannot switch the selected prompt or erase its managed policy. Other providers receive the optional internal parameter as None; existing engine/tool policy, grants, version/preflight gates and managed-v1 refusal remain.

Idempotent reuse remains before this new-allocation gate: an existing matching terminal is returned even if its install file is now absent, with no profile read or new allocation. The snapshot is in-process launch state; this increment does not claim durable snapshot reconstruction after an API restart.
