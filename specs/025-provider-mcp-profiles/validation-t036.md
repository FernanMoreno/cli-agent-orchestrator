# T036 — expanded catalogs and independent authority

## Integrated behavior

Seven immutable profiles now exist. Interaction and collaboration retain their exact prior sets. Coordination adds four local peer tools, supervision adds three terminal-turn tools, knowledge adds skill loading/memory recall, knowledge_writer additionally exposes memory store/outcome reporting, and elastic_worker additionally exposes completion. These five profiles extend collaboration only; ordinary collaboration never gains their operations. All profiles deny general assignment/handoff, terminal deletion, human-answer impersonation, workflow/Work/Beads/Ralph mutation and memory deletion. Unknown/future/plugin names default deny. The refreshed [catalog inventory](catalog-inventory.md) classifies every one of the **79 registered operations** across all seven profiles.

Existing shared profile parsing, immutable MCP catalog/call middleware, native envelope/filter propagation and per-profile preflight are reused. No mutable dispatch policy, global wildcard grant or native shell/file permission was added. Resources, templates and prompts stay hidden. This configuration feature is shared by CAO's MCP infrastructure; it is not live acceptance of any provider.

## Reproduced supervision defect and correction

Inspection, verification and cancellation previously checked only `_tool_denied_reason`, without establishing ownership of the target. With that coarse permission satisfied, an unrelated/unknown/mismatched target reached the action implementation. Before correction, the new profile/authority selection reproduced **22 failures and nine passing controls in 46.21 seconds**: ten missing-profile cases and twelve ownership refusals that incorrectly dispatched. The initial correction passed **31 cases** in 45.08 seconds. Those original logs/results remain preserved.

A bound caller must now present a valid identity and target ID, fetch authenticated current target metadata, and match the target's ID. Self or a directly assigned child's caller_id is allowed; unrelated/sibling targets, missing/mismatched metadata, malformed identity and lookup failures fail closed with a fixed error. Existing coarse denial short-circuits before metadata lookup. Generation strings pass unchanged to the action implementation; the recovery service and downstream Work ownership fences remain independent. Unbound operator behavior is preserved. This is an MCP caller-target boundary check, not a new broker/API identity model or a sandbox against arbitrary shell execution.
