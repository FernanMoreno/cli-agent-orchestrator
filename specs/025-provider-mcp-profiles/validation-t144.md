The new private _await_provider_operation captures contextvars.copy_context, submits partial(context.run, function, args/kwargs) to the existing default executor, and shields its private Future. It adds no new pool, thread-per-call executor, admission grant, or timeout. The Future is not an asyncio child Task exposed through all_tasks. On caller cancellation it re-shields until the actual future completes despite repeated cancellation, retrieves any worker error, and then propagates the captured cancellation. Results and ordinary error identity otherwise pass through. Request/WorkContext values reach the worker; writes in its copied context are not a new caller-state channel.

Provider construction/publication uses this helper. If cancellation lands at that step, the helper first finishes the manager operation, then CancelledError still bypasses the existing Exception rollback handler: the existing discoverable identity/resources remain as they would when cancellation landed at the following initialize await before this change. This is not a new compensation or native-cancel policy.

The failed-create remaining rollback is one synchronous closure through the same helper: cleanup provider; remove capability files only when cleanup is notFalse; remove the row only when cleanup is complete; run the existing worktree removal. Ordering, deferred-False metadata retention, best-effort exception handling, backend stop-before-private-cleanup and original error rethrow are retained. Cancellation cannot stop between these protected remaining steps. Ordinary provider cleanup errors and worktree errors retain the prior handling; after cancellation, cancellation remains the visible outcome once worker ownership finishes. No new delete authority is granted.

Scope limit: earlier awaits in the failure/uncertain/managed handling, including transition_native_child before this closure, remain outside it. This does not make the entire create/rollback/initialize/DB-delete lifetime cancellation-safe. Those existing boundaries remain under T143 and related lifecycle work.
