# T162 — publicación y retirada de sidecars entre procesos

2026-10-26, FR140/SC124. Corrección acotada de T143/OC06, comprobada con PostgreSQL real y procesos separados. [Recibos y fuentes](validation-t162.json).

Un publicador pausado después de observar una fila existente podía escribir evidencia de fallo o finalización después de que otro proceso borrara fila y sidecars. El RLock previo solo coordinaba hilos del mismo proceso. Reproducción inicial: 2FAIL/2controles secuenciales PASS; no era una aceptación nativa.

Se añade un protocolo de 256 stripes estables SHA-256 bajo el mismo log root. Los wrappers cooperantes adquieren flock antes de los leases locales; bulk adquiere stripes únicos ordenados y después IDs ordenados. La reentrancia reutiliza el descriptor, holders/waiters se cuentan antes de adquirir y los registros Python se retiran al quedar vacíos. Los archivos del pool no se borran durante la vida del protocolo. Cerrar el descriptor o morir el proceso libera el bloqueo. Fallar al adquirir impide publicar o borrar antes de SQL/escritura. Permisos de creación privados, propietario/tipo/no-follow/enlace único se conservan.

Los tests observan contención real del kernel y liberan explícitamente al publicador antes de esperar el borrado; verifican ambas clases de sidecar y retirada simple/bulk, PIDs distintos y procesos recogidos. Cubren pool acotado, colisiones/reentrancia, orden bulk, fallos de open/flock, outage y restauración de fixtures. Cuatro diagnósticos adicionales ejecutan el mismo cuerpo con PG real y rutas temporales DrvFS: PASS. DrvFS reporta0777 aunque se solicite modo privado; una condición nueva basada solo en bits reportados fue retirada antes de aceptar, manteniendo controles previos y prueba real de flock. No se cambian permisos MCP ni autenticación.
