# T049 — managed native-v1 preparation (bounded gate completed)

The first remaining group is OpenCode v1, per the user's ordered request. The old provider rejected every managed envelope, while its strict native writer could neither consume profile/filter metadata nor validate the effective native grant. T049 adds a bounded v3-only noninteraction path; legacy envelope v1/v2 and unvalidated managed-v1 interaction remain refused.

The provider rechecks its frozen v3 binding after shell readiness, applies the selected profile/filter only in a private copy, and validates each active profiled native child before backend launch. The writer consumes metadata through the existing protected canonical overlay and then enforces the original native field set. Forged policy variables are stripped, empty/partial filters stay exact, unknown command targets are refused, and source artifacts/config remain unchanged. Native MCP permission selectors are normalized only when the server name changes, preserving native action/resource order and refusing collisions.

Native preflight evaluates explicit global rules followed by selected-agent rules, using last matching action/resource and requiring allow for every offered tool. It neither depends on v1's permissive defaults nor translates permissions to v2 arrays. This matches the pinned upstream [native permission evaluation](https://raw.githubusercontent.com/anomalyco/opencode/53d1eabb61e21162157817bf677da0a4ad3332e3/packages/opencode/src/permission/index.ts) and [global/agent composition](https://raw.githubusercontent.com/anomalyco/opencode/53d1eabb61e21162157817bf677da0a4ad3332e3/packages/opencode/src/agent/agent.ts). It is a local grant check, not server operation authority.
